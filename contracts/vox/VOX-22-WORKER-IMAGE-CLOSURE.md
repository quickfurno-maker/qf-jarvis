# VOX-22 Jarvis worker image dependency closure

The **aggregated Jarvis main-based PR #336** uncovered a genuine production supply-chain failure missed by source TypeScript checks. Its worker Dockerfile builds `@qf-jarvis/api...`, transitively compiling `apps/quickfurno-gateway/src/index.ts` which dynamically imports the signed, Core-authorized VOX reader and authorizer via `../../../contracts/vox/*.mjs`. The dedicated gateway image copied `contracts/vox`, but **quickfurno-worker** omitted it, causing TS2307 at image build and blocking a signed candidate.

This patch copies the exact approved server-only `contracts/vox` into the worker **builder before compiling**, and into the runtime stage to preserve resolution if needed. It does **not** add new dependencies, change permissions, enable `QFJ_VOX_ADVISORY_ENABLED`, send WhatsApp messages, call Core, or alter business state. New source guard validates both gateway and worker builder+runtime copies, exact import paths and default-off state. Real Docker supply-chain workflow must build all three Jarvis images before any signed digest promotion. **Production and managed staging remain HOLD** until actual managed Core database backup/recovery and legitimate agent authorization/replay.
