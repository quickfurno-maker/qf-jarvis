# VOX-16B Jarvis private advisory gateway — signed, scope-checked READ ONLY

The existing QuickFurno machine-to-machine Jarvis gateway gets an optional staging-only `POST /internal/vox/v1/agent-view` read endpoint with a bounded JSON body (`agentViewToken` only), authenticated staff bearer in server request Authorization, and a server-owned injected `voxAdvisoryReader`. The injected reader must be the already reviewed `createScopedVoxAdvisoryReader` wired with existing Jarvis PostgreSQL durable replay pool, the signed view secret and the **live** `createVoxCoreSubjectAuthorizer` callback (Core current AAL2/city/assignment/HUMAN revision). The gateway itself never creates its own privilege grants or accepts browser-claimed role/city fields.

Safety: requires `QFJ_VOX_ADVISORY_ENABLED=staging` **and** a trusted injected reader; otherwise 503. Invalid staff token/schema, signed token, Core authorization, replay or DB state fail closed. All safe output properties are re-projected; no phone, provider payload, messages, wallets or bearer tokens returned. No action executor/consent mutation. This is a **source gateway route**, not an enabled or deployed Jarvis runtime because actual credentials/wiring, isolated private ingress, origin/proxy auth, durable DB migration, real MFA/consent and signed Staging deployment still need certification.

Do not expose this private gateway directly to the public internet, log Authorization, enable the flag or claim live agent runtime until tested with signed builds, the pinned Core staging origin, actual database and owner consent.
