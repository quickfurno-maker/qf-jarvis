# ADR-0159 — RAG V2 production hardening and operational boundaries

**Status:** Accepted for implementation.
**Date:** 2026-09-23
**Supersedes:** no Riya continuity/privacy decision.

## Decision

RAG V2 remains the single governed retrieval plane for Riya, Anisha and Aarohi, but production use adds the following mandatory controls.

1. Subject-linked records are refused before semantic normalization, embedding or persistence.
2. Rerankers declare LOCAL or HOSTED execution class; LOCAL_ONLY content may reach only LOCAL reranking.
3. A grounded REPLY must return at least one authorized citation.
4. The production worker binds an exact active SEALED knowledge revision and exact embedding model before READY.
5. Production database TLS accepts verify-full only.
6. Worker signing and embedding credentials are separate secret files rather than inline configuration.
7. CI/development PostgreSQL includes pgvector and is pinned by image digest.
8. Embeddings may be reused only by exact content digest plus exact embedding-model identity after current-record data-class admission.
9. Old inactive releases are retired only through a maintainer-only scoped function that can touch documents belonging to the selected release and never unrelated staging rows.
10. Capacity evidence is generated by a destructive loopback-only benchmark; managed databases are refused as benchmark targets.
11. The single-owner worker emits one strict content-free operational observation file, including bounded model/RAG latency and aggregate RAG outcome counts; Jarvis OS may read it only through the governed read-source boundary, rejects stale/malformed snapshots, and gains no database, provider, Core or execution authority.

## Authority boundary

This ADR changes no business authority. Retrieval ranks evidence; governed knowledge decides whether evidence is readable; the model drafts; QuickFurno Core authorizes business/communication effects.

Mastra remains an orchestration shell. Temporal remains durable coordination only. Neither gains knowledge, execution or business authority.

## Source ingestion

Document-format adapters stay outside the serving and index cores. PDF/DOCX/HTML/CMS/Drive/Notion integration must terminate in bounded governed source records after type validation, scanning and extraction provenance.

## Scale boundary

The current file spool and process-local replay protections are approved only for the existing single-owner deployment shape. Multi-replica operation requires a shared durable queue/claim authority first.

## Riya persistence is explicitly not authorized here

ADR-0095 and ADR-0104 remain controlling for migrations 0011 and 0012. This ADR neither selects a retention period nor authorizes live client-project continuity in managed QF-Jarvis PostgreSQL.

A superseding owner decision is still required for data classification, purpose limitation, retention and erasure before that production persistence path can be activated.

## Live certification of grounded paths

The production RAG composition MUST NOT rely on an ungrounded provider certification alone. JF-5B therefore carries bounded synthetic hybrid-grounding fixtures for RIYA, ANISHA and AAROHI. Those cases traverse the same runtime grounding bridge used by production, place the governed record in the model-only payload, and PASS only when the accepted structured result cites the exact supplied synthetic knowledge id/version.

At least one fixture contains adversarial instruction-like document text. The document remains reference data and may not override system instructions or QuickFurno authority.

Riya's evolution, grounded-evolution and grounded-reply prompt definitions intentionally have the same prompt family, version, body and digest. One accepted CLIENT evidence binding therefore names the exact reviewed bytes for all three task-class variants. Production seal binding exposes that same immutable binding to all three Riya runtime surfaces; it does not synthesize a second prompt identity.

This changes the JF-5B case-set digest and therefore requires a fresh live JF-5B run, human review and JF-5C seal for the new repository SHA before production activation.
